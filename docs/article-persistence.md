# 文章持久化

本改动只更新代码。现有线上版本要在后续发布包含该改动的前后端后，才会使用文章数据库。

## 使用方式

1. 登录后从 PostgreSQL 读取当前账号的文章。
2. 新建、编辑、改标题、移动目录、删除及恢复文章后自动保存。停止编辑约 700ms 后提交；持续编辑最多间隔 5 秒触发一次提交。
3. 顶栏显示“保存中…”或“已保存”。可以点击状态按钮或按 `Ctrl+S`（macOS 为 `⌘S`）立即保存。
4. 正常退出登录前等待编辑器最后一次序列化及数据库保存。保存失败时保留当前页面，方便重试；尚未保存时关闭或刷新页面会触发浏览器提示。
5. 同一账号在新浏览器重新登录，可以读取已保存的正文、富文本格式、图片、目录、回收站和发布历史。

网络或服务故障时，已有缓存仍可编辑，未上传修改按账号保存在浏览器，恢复网络后重试。浏览器缓存配额不足会显示提示，此时未保存内容只在当前页面，请保持页面打开直到显示“已保存”。首次打开且没有缓存时，读取失败会显示工作区加载错误。

## 旧文章迁移与多窗口冲突

旧版 `block-notes-docs` 和 `block-notes-docs-user:<用户ID>` 会在首次登录时自动导入。早期未分账号的缓存归入该浏览器第一个登录的账号。

- 云端为空：保留文章原来的 ID、顺序、目录和回收站状态。
- 云端已有文章：相同文章不重复导入；同 ID 的不同内容作为新文章保存，并保留导入目录关系。
- 已迁移且没有待上传修改的缓存：以后以云端读取结果为准，避免把已永久删除的文章带回来。
- 多窗口或设备同时保存：服务端检查版本号，旧版本写入返回 `409 ARTICLE_REVISION_CONFLICT`，不会覆盖另一端内容。点击“恢复本地草稿”，将不同内容保存成新草稿，并载入最新云端工作区。冲突中的删除操作不会自动删除最新云端文章。

这提供跨设备持久化和冲突保护。已打开页面在重新登录、重试读取或恢复冲突时获取最新云端内容；逐字实时协同仍由独立的协同接口负责。

## 数据库与接口

新增迁移 [005_articles.sql](../apps/api/migrations/005_articles.sql)：

- `article_workspaces`：用户、版本号、当前文章、发布记录及最后一次写入 ID。
- `articles`：文章标题、JSONB 正文、作者、地点、状态、顺序、父文章和创建/更新时间、回收站时间。
- 文章主键为 `(user_id, id)`，父文章也使用同账号复合外键；历史字符串 ID 与新 UUID 都可以迁移。

正式 API 入口显式注入 PostgreSQL 仓库，启动时按现有迁移机制自动应用新增 SQL。也可执行 `pnpm db:migrate`。不要修改已应用的旧迁移。

| 接口                          | 用途                                                           |
| ----------------------------- | -------------------------------------------------------------- |
| `GET /api/articles/workspace` | 获取当前 JWT 用户的文章工作区与 `revision`                     |
| `PUT /api/articles/workspace` | 提交工作区及预期 `revision`、UUID `writeId`，返回新 `revision` |

两个接口都要求登录；用户 ID 只从验证后的 JWT 获取，客户端不能指定其他用户。写请求校验 Origin 和数据结构。正文、目录、回收站及发布记录在同一个事务中提交；相同 `writeId` 和内容重试不会重复增版本，内容不同则拒绝。

图片保存为正文中的 data URL，保留实际字节，拒绝仅当前页面有效的 `blob:` 地址。沿用 API 的 **16MB 请求上限**，目前每次保存提交整个账号工作区；大量文章/图片超出上限时会显示错误，需要减少内容。后续扩展可改为按文章增量保存并将图片迁入对象存储。

## 代码位置

- `apps/api/src/{routes,services,repositories}/` 中的 `article*` 文件：请求验证、目录校验及数据库事务。
- `apps/api/src/type/article.ts`：与前端文档格式对应的严格校验规则。
- `apps/web/src/services/articles-api.ts`：复用现有认证请求、续期机制。
- `apps/web/src/store/docsStore.ts`：读取、迁移、自动保存、失败重试与账号切换隔离。
- `apps/web/src/store/article-recovery.ts`：旧缓存导入与冲突恢复。
- `apps/web/src/components/editor/ArticleSyncStatus.tsx`：保存状态、重试、快捷键及离开页面保护。
- `BlockSuiteEditor.tsx` / `EditorColumn.tsx`：保存前刷新编辑缓冲；旧编辑器的异步回调不能写入新账号或恢复后的工作区。

## 本地验证

启动本地 PostgreSQL 后执行：

```powershell
pnpm db:up
$env:ARTICLE_TEST_DATABASE_URL='postgresql://automatic:automatic@127.0.0.1:5432/automatic'
$env:COLLABORATION_TEST_DATABASE_URL=$env:ARTICLE_TEST_DATABASE_URL
pnpm check
pnpm format:check
```

数据库集成测试创建独立临时 schema，结束后删除该 schema，不修改已有账号或文章。未提供集成测试数据库变量时这些测试会跳过；GitHub CI 已配置独立 PostgreSQL 服务和两个变量。

测试覆盖富文本/图片往返、账号隔离、目录及回收站、永久删除、真实 PostgreSQL 连接重建、事务失败回滚、并发/重复提交、旧缓存迁移、离线重试、保存中的继续编辑、账号切换及冲突恢复。

人工检查：登录 → 编辑标题/正文并插入图片 → 等待“已保存” → 退出重新登录 → 用无本地缓存的新浏览器登录 → 验证内容。另开两个窗口修改同一账号的文章，确认旧版本保存提示冲突，恢复后的本地内容成为新草稿而云端原稿仍在。
